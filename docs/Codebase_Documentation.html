1. Project Overview and Architecture

This codebase implements a complete machine learning pipeline for classifying four lower-limb movements — Walking (WAK), Going Upstairs (UPS), Going Downstairs (DNS), and Standing Up (STDUP) — from surface electromyography (sEMG) signals recorded from 9 muscles of the lower limb. The dataset used is the SIAT_LLMD20230404 benchmark, containing recordings from 40 healthy subjects performing 16 movement types, of which 4 are selected for this study.

The pipeline follows a principled experimental methodology designed to measure how well models generalize to unseen individuals. It evaluates three model families under two cross-validation paradigms:

ModelTypeKey Hyperparameters
SVM (RBF kernel)ClassicalC ∈ {1, 5, 10}, gamma = "scale", StandardScaler in Pipeline
Random ForestClassicaln_estimators ∈ {200, 400, 500}, max_depth ∈ {None, 10}
1D CNN (SimpleEMGCNN)Deep LearningConv1d: 32→64→128 filters, Adam lr=1e-3, early stopping (patience=5)
CV ParadigmPurposeImplementation
Subject-Dependent (SD)Within-subject baseline5-fold StratifiedKFold, windows from all subjects pooled
Leave-One-Subject-Out (LOSO)Cross-subject generalization40 outer folds (1 subject held out each), nested GridSearchCV for classicals, early stopping for CNN

The generalization gap (ΔF1 = F1SD − F1LOSO) is the central metric, quantifying how much performance degrades when a model encounters a completely new individual.

The primary evaluation metric is Macro F1-Score, chosen because it is class-frequency-independent and thus suitable for the moderate class imbalance present in the dataset. Supporting metrics include Balanced Accuracy and Overall Accuracy.

End-to-End Pipeline Flow:

Raw CSVs (40 subjects × 4 movements)
  ↓ preprocess_emg.py — bandpass filter → envelope → sliding windows → .npz + meta.csv
  ↓ extract_features.py — MAV, RMS, WL, ZC (+WAMP, wavelet, freq) → features .npz
  ↓ merge_freq_wavelet_features.py — combine wavelet + freq → 81-dim full set
  ↓ train_classical_patched.py / train_cnn_subjectdep.py — SD evaluation
  ↓ train_classical_loso.py / train_cnn_loso.py — LOSO with nested tuning
  ↓ Optimization stages: Norm ablation → Feature selection → CNN augmentation
  ↓ Ensemble evaluation & statistical validation
  ↓ Analysis & Plotting scripts — generalization gap, statistical tests, visualisations

Data flow through the pipeline: Raw CSV files are first loaded and aligned by preprocess_emg.py, which outputs compressed NumPy archives (.npz) containing 3D window arrays of shape (N, C, T) where N is the number of windows, C is the number of sEMG channels (9), and T is the number of time samples per window (dependent on window length and sampling rate). A companion metadata CSV is generated with one row per window, recording subject ID, movement type, label confidence, and timing information. This 1:1 alignment between NPZ rows and CSV rows is a critical invariant maintained throughout the entire pipeline.

3. Stage 1 — Data Preprocessing

preprocess_emg.py
702 lines  |  Loads raw sEMG CSVs, applies signal conditioning, segments into labelled sliding windows, outputs compressed NPZ + metadata CSV.

3.1 Configuration via Dataclass

All preprocessing parameters are encapsulated in a PreprocessConfig dataclass, making the entire pipeline reproducible and auditable. Every run serialises its configuration to a JSON file alongside the output.

@dataclass
class PreprocessConfig:
    base_dir: Path
    bandpass_low: float = 20.0      # Hz — removes motion artefact below 20 Hz
    bandpass_high: float = 450.0    # Hz — removes high-freq noise above 450 Hz
    bandpass_order: int = 4         # 4th-order Butterworth (standard for sEMG)
    envelope_ms: float = 50.0      # 50ms RMS envelope smoothing window
    win_ms: float = 150.0          # Sliding window length in ms
    overlap: float = 0.5           # 50% overlap between consecutive windows
    min_label_conf: float = 0.60   # 60% majority-label confidence threshold
    drop_none_labels: bool = True
    drop_wak_unlabelled_zero: bool = True
    keep_only_active_stdup: bool = False
Design Decision — Bandpass 20–450 Hz: The 20 Hz lower cutoff removes motion artefacts and baseline drift common in lower-limb sEMG. The 450 Hz upper cutoff is well below the Nyquist frequency (~960 Hz at 1920 Hz sampling) and removes high-frequency noise while preserving the muscle activation frequency band (20–500 Hz per SENIAM guidelines). A 4th-order Butterworth provides a sharp roll-off without excessive phase distortion thanks to zero-phase filtering via filtfilt.

3.2 Data Loading and Label Alignment

Each subject's movement trial consists of two CSV files: a data file (containing Time, 8 kinematic, 8 kinetic, and 9 sEMG columns) and a label file (Time + Status). Since data and labels are sampled independently, temporal alignment is performed using pandas.merge_asof with nearest-neighbour matching and a tolerance of half a sample period:

def align_labels_to_data_by_time(data_time, label_df, status_col, tol):
    # Merge labels onto data timestamps using nearest-neighbour
    merged = pd.merge_asof(d, l, on="Time", direction="nearest", tolerance=tol)
    return aligned_status

The sampling rate is not hardcoded; instead, it is estimated from the median inter-sample interval of each trial's Time column using estimate_fs(). This makes the pipeline robust to minor variations across files. The estimated rate is approximately 1920 Hz (median dt ≈ 0.000521s).

3.3 Signal Conditioning

Two signal conditioning steps are applied sequentially to each sEMG channel:

Bandpass Filtering: A 4th-order Butterworth bandpass filter is designed using scipy.signal.butter and applied with zero-phase filtering via scipy.signal.filtfilt. Zero-phase filtering applies the filter forward and then backward, eliminating phase distortion while doubling the effective filter order to 8th-order attenuation.

def design_bandpass(fs, low, high, order):
    nyq = 0.5 * fs
    b, a = butter(order, [low/nyq, high/nyq], btype="bandpass")
    return b, a

def apply_bandpass(df, fs, cfg):
    b, a = design_bandpass(fs, cfg.bandpass_low, cfg.bandpass_high, cfg.bandpass_order)
    for col in emg_cols:
        out[col] = filtfilt(b, a, df[col].to_numpy(dtype=float))

Envelope Extraction: Full-wave rectification (absolute value) followed by a centred rolling mean with a 50ms window. This extracts the amplitude envelope of the sEMG signal, which represents the overall muscle activation level. The choice of 50ms balances temporal resolution with smoothness — short enough to track rapid movement transitions, long enough to suppress individual motor unit action potential spikes.

def rectify_and_envelope(df, fs, cfg):
    win_samples = int(round(cfg.envelope_ms * fs / 1000.0))
    for col in emg_cols:
        rect = np.abs(df[col].to_numpy(dtype=float))
        out[col] = pd.Series(rect).rolling(win_samples, center=True, min_periods=1).mean()

3.4 Sliding Window Segmentation

The continuous signal is segmented into fixed-length overlapping windows. Both the bandpass-filtered ("raw") and envelope signals are windowed in parallel — the raw windows are used for CNN input (which learns its own representations), while the envelope windows serve as a fallback for feature extraction.

win_samples = int(round(cfg.win_ms * fs / 1000.0))  # e.g., 150ms × 1920Hz ≈ 288 samples
step = int(round(win_samples * (1.0 - overlap)))       # 50% overlap → step = 144 samples

for start in range(0, len(df) - win_samples + 1, step):
    end = start + win_samples
    # Extract (C, T) window from both raw and envelope DataFrames
    X_raw_list.append(win_raw[emg_cols].to_numpy())
    X_env_list.append(win_env[emg_cols].to_numpy())

Each window receives a label determined by majority voting: the most frequent label within the window's span is chosen, and its proportion becomes the confidence score. Windows failing the 60% confidence threshold are discarded — this eliminates transition windows where the subject is mid-movement-change.

def majority_label_with_conf(status_series):
    mode = status_series.dropna().mode().iloc[0]
    conf = (status_series == mode).mean()
    return mode, conf  # e.g., ("WAK", 0.85) → 85% of samples are WAK
Design Decision — 60% Confidence Threshold: A threshold of 0.60 ensures that at least 60% of a window's samples share the same label. This is a deliberate trade-off: too strict (e.g., 90%) would discard too many windows near movement transitions and reduce training data; too lenient (e.g., 30%) would introduce noisy labels. The 60% value was chosen as it is commonly used in the sEMG windowing literature.

3.5 Ablation Mode

The script supports an --ablation flag that automatically runs preprocessing for multiple window lengths (default: 150ms and 250ms) in a single invocation. Each run gets an auto-generated tag encoding its parameters (e.g., w150_ov50_conf60_AorR), ensuring output files are uniquely named and traceable.

3.6 Output Format

The primary output is a compressed NPZ file containing two arrays: X_raw (bandpass-filtered windows) and X_env (envelope windows), both stored in (N, C, T) format — N windows, C=9 channels, T time samples. An internal function _ensure_nct() detects and auto-transposes arrays if the original extraction yields (N, T, C). The companion CSV contains per-window metadata, and summary statistics (window counts by movement and subject) are saved as both CSV and JSON.

4. Stage 2 — Feature Extraction

extract_features.py
478 lines  |  Computes time-domain, frequency-domain, and wavelet features from each window. Outputs 2D feature matrices (N, F) as NPZ files.

4.1 Feature Functions

Nine feature extraction functions are implemented, each operating on a per-channel basis (input shape: (C, T), output shape: (C,)). They fall into three categories:

Time-Domain Features (Base Set — 36 dimensions)

FeatureFormulaDimensionsPurpose
MAVmean(|x|)9Average muscle activation amplitude
RMSsqrt(mean(x²))9Signal power proxy (energy content)
WLsum(|diff(x)|)9Signal complexity / waveform length
ZCCount of sign changes where |Δx| ≥ threshold9Frequency information proxy
def feat_mav(x):    return np.mean(np.abs(x), axis=-1)
def feat_rms(x):    return np.sqrt(np.mean(x**2, axis=-1))
def feat_wl(x):     return np.sum(np.abs(np.diff(x, axis=-1)), axis=-1)
def feat_zc(x, thr=1e-6):
    s = np.sign(x); s[s == 0] = 1
    sign_change = (s[..., 1:] * s[..., :-1]) < 0
    delta = np.abs(x[..., 1:] - x[..., :-1]) >= thr
    return np.sum(sign_change & delta, axis=-1)
Design Decision — Zero Crossing Threshold: A tiny threshold (1e-6) is used rather than zero to prevent noise-induced false crossings. This is standard practice in sEMG processing, where low-amplitude noise around the zero line could otherwise inflate ZC counts.

Extended Features (WAMP + Wavelet — adds 18 dimensions)

FeatureDimensionsPurpose
WAMP (Willison Amplitude)9Counts amplitude changes above threshold — correlates with motor unit firing
Wavelet Energy (db4, level 2)9Multi-resolution frequency decomposition energy at detail level 2
def feat_wavelet_energy(x, wavelet="db4", level=2):
    import pywt
    for c in range(C):
        coeffs = pywt.wavedec(x[c], wavelet=wavelet, level=level)
        cD_L = coeffs[1]  # Detail coefficients at the specified level
        out[c] = np.sum(np.square(cD_L))  # Energy = sum of squared coefficients

The Daubechies-4 (db4) wavelet at decomposition level 2 was chosen because db4 provides a good balance between time and frequency localisation for transient sEMG bursts. Level 2 captures frequency components in roughly the 240–480 Hz band (at 1920 Hz sampling), which corresponds to the upper sEMG activity range.

Frequency-Domain Features (adds 27 dimensions)

FeatureDimensionsPurpose
MNF (Mean Frequency)9Power-weighted average frequency — shifts with fatigue
MDF (Median Frequency)9Frequency at 50% cumulative power — more robust to noise than MNF
Spectral Power (log)9Total signal energy in frequency domain (log-scaled for stability)
def feat_mean_freq(x, fs=2000.0):
    freqs = np.fft.rfftfreq(T, d=1.0 / fs)
    spectrum = np.abs(np.fft.rfft(x[c])) ** 2  # Power spectral density
    return np.sum(freqs * spectrum) / np.sum(spectrum)  # MNF = weighted average freq

def feat_spectral_power(x, fs=2000.0):
    spectrum = np.abs(np.fft.rfft(x[c])) ** 2
    return np.log1p(np.sum(spectrum))  # log(1 + total_power) for numerical stability
Design Decision — log1p for Spectral Power: Raw spectral power can span many orders of magnitude across channels and subjects. Using np.log1p() (i.e., log(1+x)) compresses the dynamic range while remaining monotonic. The "+1" prevents log(0) for silent channels.

6. Stage 3 — Subject-Dependent Training (Classical)

train_classical_patched.py
589 lines  |  Evaluates SVM, Random Forest, and LDA under subject-dependent 5-fold stratified cross-validation. Includes detailed timing, support vector diagnostics, and prediction saving.

6.1 Model Construction

Three classifiers are built via build_models():

def build_models(seed, svm_scale, svm_c, rf_max_depth, rf_n_estimators, include_lda):
    # SVM: optionally wrapped in Pipeline with StandardScaler
    if svm_scale:
        svm = Pipeline([
            ("scaler", StandardScaler()),
            ("svc", SVC(kernel="rbf", C=svm_c, gamma="scale", class_weight="balanced")),
        ])

    # RF: no scaling needed (tree-based, scale-invariant)
    rf = RandomForestClassifier(
        n_estimators=rf_n_estimators, n_jobs=-1,
        class_weight="balanced_subsample", max_depth=rf_max_depth,
    )

    # LDA: always scaled (assumes Gaussian features)
    lda = Pipeline([("scaler", StandardScaler()), ("lda", LinearDiscriminantAnalysis())])
Design Decision — StandardScaler in Pipeline: For SVM and LDA, StandardScaler is placed inside an sklearn Pipeline. This ensures that the scaler is fitted only on the training fold and transforms both training and test folds identically — preventing normalisation leakage. RF does not require scaling because decision trees split on feature thresholds and are invariant to monotonic transformations.
Design Decision — class_weight="balanced": Both SVM and RF use class weighting to handle the moderate imbalance among the four movement classes. For SVM, "balanced" adjusts the C parameter inversely proportional to class frequencies (Ck = C × n_total / (n_classes × n_k)). For RF, "balanced_subsample" recomputes weights for each bootstrap sample, which is more robust when combined with random subsampling.

6.2 Cross-Validation Loop

The eval_subject_dependent_cv() function implements 5-fold StratifiedKFold, tracking per-fold accuracy, balanced accuracy, and macro F1. It also records computational diagnostics: fit time, prediction time, inference latency per window, and SVM-specific metrics (number of support vectors, fraction of training data used as support vectors, solver iterations).

y_true_full = np.full(len(y), fill_value=-1, dtype=np.int32)

train_cnn_subjectdep.py

7.1 CNN Architecture — SimpleEMGCNN

A compact three-layer 1D convolutional network processes raw sEMG windows of shape (C, T) where C=9 (channels) and T varies with window length:

class SimpleEMGCNN(nn.Module):
    def __init__(self, in_ch, n_classes, dropout=0.25):
        self.net = nn.Sequential(
            nn.Conv1d(in_ch, 32, kernel_size=9, padding=4),   # 9 → 32 channels
            nn.BatchNorm1d(32), nn.ReLU(), nn.MaxPool1d(2),

            nn.Conv1d(32, 64, kernel_size=7, padding=3),   # 32 → 64 channels
            nn.BatchNorm1d(64), nn.ReLU(), nn.MaxPool1d(2),

            nn.Conv1d(64, 128, kernel_size=5, padding=2),  # 64 → 128 channels
            nn.BatchNorm1d(128), nn.ReLU(),

            nn.AdaptiveAvgPool1d(1),  # Global average pooling → (N, 128, 1)
        )
        self.head = nn.Sequential(
            nn.Flatten(),              # → (N, 128)
            nn.Dropout(dropout),       # 25% dropout for regularisation
            nn.Linear(128, n_classes),  # 128 → 4 (movement classes)
        )
Design Decision — Decreasing Kernel Sizes (9→7→5): Larger kernels in early layers capture broad temporal patterns (corresponding to ~4.7ms, ~3.6ms, ~2.6ms at 1920 Hz), while smaller kernels in later layers refine finer-grained features. This follows the common practice in 1D signal processing CNNs.
Design Decision — AdaptiveAvgPool1d(1): This pooling layer collapses the temporal dimension regardless of input length, making the architecture compatible with different window sizes (150ms and 250ms produce different T values). It also acts as a regulariser by averaging over all time steps.

7.2 Per-Channel Z-Score Normalisation

Crucially, normalisation statistics are computed only on training data and then applied to both training and test sets:

def zscore_fit(Xtr, eps=1e-8):
    mu = Xtr.mean(axis=(0, 2), keepdims=True)  # Mean across N and T → shape (1, C, 1)
    sd = Xtr.std(axis=(0, 2), keepdims=True) + eps
    return mu, sd

This prevents information leakage from test subjects into the normalisation parameters.

7.3 Overfit Sanity Check

The script includes a patched overfit test that uses stratified random subsampling rather than taking the first N rows (which could accidentally under-represent some classes). The function make_stratified_subset() allocates samples proportionally to class frequency, ensuring at least one sample per class when possible. Optional flags disable dropout and freeze BatchNorm for the overfit test, removing all regularisation to verify the model can memorise small datasets — a standard sanity check before running expensive LOSO experiments.

8. Stage 5 — Leave-One-Subject-Out (Classical)

train_classical_loso.py
344 lines  |  Nested LOSO cross-validation for SVM and RF with inner GroupKFold hyperparameter tuning. Includes checkpointing, resume support, and per-fold prediction flushing.

8.1 LOSO Protocol

The outer loop holds out one subject at a time (40 folds total). For each fold, the remaining 39 subjects' data forms the training set. Hyperparameters are tuned via an inner GroupKFold cross-validation on the training subjects only, ensuring the held-out subject is never seen during any part of the training or tuning process.

for heldout in unique_subjects:
    te_mask = (subjects == heldout)
    Xtr, ytr, gtr = X[~te_mask], y[~te_mask], subjects[~te_mask]
    Xte, yte = X[te_mask], y[te_mask]

    # Inner CV: subject-grouped splits on training subjects only
    inner_cv = GroupKFold(n_splits=min(5, n_train_groups))

    search = GridSearchCV(pipe, param_grid,
        scoring="f1_macro",
        cv=inner_cv.split(Xtr, ytr, groups=gtr),  # Groups = subject IDs
        refit=True)

    search.fit(Xtr, ytr)
    yhat = search.best_estimator_.predict(Xte)
Design Decision — GroupKFold for Inner CV: Using GroupKFold with subject IDs as groups ensures that no subject appears in both the inner training and inner validation sets. This is critical for preventing within-subject leakage during hyperparameter selection. Using regular KFold would allow windows from the same subject to appear on both sides, producing over-optimistic tuning scores.

8.2 Pipeline with StandardScaler

Both SVM and RF are wrapped in sklearn Pipelines that include StandardScaler as the first step. A custom ToFloat32 transformer follows the scaler to ensure consistent dtype (important for SVM's numerical stability with float32 features):

class ToFloat32(BaseEstimator, TransformerMixin):
    def fit(self, X, y=None): return self
    def transform(self, X): return X.astype(np.float32, copy=False)

steps = [("scaler", StandardScaler()), ("to32", ToFloat32()),
         ("clf", SVC(kernel="rbf", class_weight="balanced", cache_size=500))]
pipe = Pipeline(steps)

9. Stage 6 — Leave-One-Subject-Out (CNN)

train_cnn_loso.py
421 lines  |  LOSO evaluation for SimpleEMGCNN with per-channel train-only normalisation, validation-based early stopping, class-weighted loss, mixed precision support, and resume capability.

9.1 Train-Only Normalisation

Per-channel statistics are computed exclusively on the training subjects' data using compute_train_norm(), then applied to validation and test sets via apply_norm(). This is the CNN equivalent of the StandardScaler in the classical pipeline:

def compute_train_norm(X_train):
    # X_train: (N, C, T) — mean/std across N and T for each channel
    mean = X_train.mean(axis=(0, 2), keepdims=True)   # shape (1, C, 1)
    std = X_train.std(axis=(0, 2), keepdims=True)
    std = np.where(std < 1e-8, 1.0, std)  # Prevent division by zero
    return mean, std

9.2 Validation Subject Selection

Within each LOSO fold, 15% of the remaining 39 training subjects are randomly selected as a validation set for early stopping. The selection uses a seeded RNG with seed = base_seed + heldout_subject_id, ensuring deterministic yet fold-specific splits.

9.3 Class-Weighted Cross-Entropy

Inverse-frequency weighting compensates for class imbalance:

def class_weights_from_y(y, n_classes):
    counts = np.bincount(y, minlength=n_classes)
    w = counts.sum() / np.maximum(counts, 1.0)  # Inverse frequency
    w = w / w.mean()  # Normalise so average weight = 1
    return torch.tensor(w)

9.4 Training Loop with Early Stopping

The model trains for up to 25 epochs. After each epoch, the validation loss is checked; if it has not improved for 5 consecutive epochs, training halts and the best state is restored.

9.5 GPU Acceleration and Memory Management

The script uses cudnn.benchmark = True for automatic kernel selection, optional mixed-precision training via torch.amp, and aggressive memory cleanup between LOSO folds (deleting models/loaders + gc.collect() + torch.cuda.empty_cache()).

16.1 Wilcoxon Signed-Rank Test (Manual Implementation)

Since scipy is not always available in all environments, the Wilcoxon test is implemented from scratch with proper tie handling:

def wilcoxon_signed_rank(x, y):
    d = x - y
    d = d[d != 0]  # Remove zero differences
    abs_d = np.abs(d)
    # Assign ranks with average tie-breaking
    # Compute W+ (sum of ranks where d > 0) and W- (sum where d < 0)
    # Normal approximation: z = (W+ − μ_W) / σ_W
    mean_W = n * (n + 1) / 4.0
    std_W = math.sqrt(n * (n + 1) * (2 * n + 1) / 24.0)
    z = (W_plus - mean_W) / std_W
    p = 2 * (1 - normal_cdf(abs(z)))  # Two-sided p-value
    return W_plus, W_minus, z, p, n

Three pairwise comparisons are conducted: RF vs SVM, RF vs CNN, and SVM vs CNN, all on per-subject LOSO F1 scores.

16.2 95% Confidence Intervals

Computed using the standard normal approximation (z = 1.96 for 95% CI): CI = mean ± 1.96 × SE, where SE = SD / √n.

16.3 Subject Difficulty Analysis

Subjects are ranked by average F1 across all three models. The 5 hardest and 5 easiest subjects are identified. Cross-model correlations (Pearson r and Spearman ρ) are computed to determine whether subjects that are difficult for one model tend to be difficult for all models.

20. Design Decisions and Justifications

20.1 Why Macro F1 as the Primary Metric?

Macro F1 computes the F1-score independently for each class and then takes the unweighted mean. This treats all four movement classes equally regardless of their frequency in the dataset, which is appropriate because: (a) the classes have moderate imbalance (WAK has the most windows, STDUP the fewest), and (b) correctly classifying rare movements is clinically as important as common ones. Balanced accuracy is reported as a supporting metric for comparison with related work.

20.2 Why Two Window Lengths (150ms and 250ms)?

Shorter windows (150ms) provide faster response times but contain fewer samples per channel (~288 at 1920 Hz), potentially limiting feature discriminability. Longer windows (250ms) contain more samples (~480), enabling richer feature extraction and more stable frequency estimates, but increase classification latency. The ablation study compares both to find the optimal trade-off. The 250ms window was established as the winner and used for all LOSO experiments.

20.3 Why Both Raw and Envelope Signals?

The CNN receives raw (bandpass-filtered) signals because convolutions can learn their own features from the full signal. The envelope representation is preserved as a fallback and for interpretability (feature values computed on the envelope have clearer physical meaning). The SD CNN experiments showed that the envelope representation (X_env) with z-score normalisation produced the best results.

20.4 Why Nested LOSO Instead of Simple LOSO?

Simple LOSO would train with fixed hyperparameters across all 40 folds. Nested LOSO (with inner GroupKFold) tunes hyperparameters separately for each held-out subject, ensuring that: (a) the hyperparameter selection itself does not leak test data, and (b) the model can adapt to the training distribution of each specific fold, which may vary as different subjects have different signal characteristics.

20.5 Why StandardScaler Inside Pipeline (Not Before)?

Applying StandardScaler globally before CV would leak test set statistics into training. By placing it inside an sklearn Pipeline, the scaler is fitted on the training fold only and applied to the test fold — this is the standard leak-proof approach. This is particularly important for LOSO, where the held-out subject may have significantly different signal amplitudes.

20.6 Why No Deep Transfer Learning?

While the literature review discusses transfer learning approaches, the experimental design focuses on establishing strong classical and CNN baselines with properly evaluated generalization gaps. Transfer learning is identified as a promising future direction but was not implemented in this iteration due to the additional complexity of pre-training schemes and domain adaptation methods.

20.7 Why Per-Subject Normalisation?

Normalisation ablation demonstrated that per-subject z-score normalisation removes inter-subject amplitude variation, which is critical for LOSO generalization. This strategy improves SVM by 6.9pp, RF by 5.1pp, and CNN by 7.2pp (all p < 0.0001). Per-subject normalisation is more robust to subject-specific sensor placement and skin impedance variations.

20.8 Why Hard Majority Vote for Ensemble?

Hard majority voting is simple, interpretable, and effective for combining heterogeneous models (classical vs deep learning). It exploits complementary error patterns: where SVM errs, RF may succeed, and vice versa. Soft voting (probability averaging) was tested but provided no additional benefit and increased complexity.

20.9 Why Freq-72 as Primary Feature Set?

4-way feature set comparison (base-36, ext-54, freq-72, combined-81) showed that the Freq-72 set maximises classical model performance under LOSO. Frequency-domain features (MNF, MDF, spectral power) capture information about muscle fatigue and movement dynamics that wavelet features do not, while avoiding the overfitting risk of the full 81-dimensional set.
